[[ruby-conventions-architecture]]
=== Architecture and responsibility

Choose a Ruby form from the role and lifecycle of the code, never from a target class-to-module ratio.

[[ruby-convention-role-based-types]]
==== Choose classes and modules by role

Rule:: Use a class for stateful entities, lifecycle collaborators, value records, errors, and framework-required subclasses;
use a module for namespaces, stateless operations, protocols designed for inclusion, filters, and compatibility facades.

Rationale:: Role and lifecycle expose design intent, while class-to-module ratios say nothing reliable about maintainability.

Enforcement:: `doc-only`; reviewed in architecture review.
+
No ratio is measured or gated.

.Good: A change carries identity and release state in an instance.
[source,ruby]
----
class Change
  def initialize attrs = {}, release:
    @release = release
    @summ = attrs['summ']
  end
end
----
Source pattern: `releasehx/lib/releasehx/rhyml/change.rb`.

.Bad: A stateless namespace is instantiated without a lifecycle.
[source,ruby]
----
class AsciiDoc
  def initialize; end
  def load_attributes path
    # Pure conversion with no retained state.
  end
end
----
Source pattern: `Counterexample derived from asciisourcerer/lib/sourcerer/asciidoc.rb`.

Migration:: Existing role mismatches are changed only when their behavior or dependencies are already changing.
